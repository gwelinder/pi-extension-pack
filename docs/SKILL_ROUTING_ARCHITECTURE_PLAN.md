# Skill routing architecture

Updated: 2026-07-14

## Decision

Pi now uses one `skill-gateway` extension instead of active `skill-router` plus `skill-bundle-router` layers.

Pi's native resource loader still discovers and deduplicates skills and registers `/skill:*` commands. On each routed turn, the gateway removes Pi's generated `<available_skills>` XML block from the model prompt, searches the catalog locally, and may inject one bounded relevant recommendation. The model uses the same `skill_lookup` tool to search and to load an exact skill body.

This avoids mutating third-party `SKILL.md` frontmatter merely to control Pi visibility.

## Runtime flow

1. Pi discovers global, project, package, and explicit skills normally.
2. `skill-gateway` receives the resolved catalog from `systemPromptOptions.skills`.
3. In `routed` mode it removes only the exact skill section generated by Pi's `formatSkillsForPrompt()`.
4. A local TF-IDF search plus curated bundle priors evaluates the current external prompt.
5. If confidence clears the threshold, the gateway appends at most two candidates under a hard character budget.
6. The model calls:
   - `skill_lookup({query})` to search;
   - `skill_lookup({name})` to load the selected `SKILL.md`.
7. Oversized skills load in bounded 16k-character chunks with an explicit continuation offset instead of flooding one turn.
8. Relative references are resolved against the returned skill base directory.

The filesystem fallback allows an explicit `pi --no-skills` evaluation lane, but normal routed operation intentionally keeps native discovery and slash commands.

## Measured result

Matched OpenAI Codex/Pi probes with the same five-tool surface measured:

- native prompt: 34,753 system characters;
- routed prompt: 2,758 system characters;
- removed: 31,995 characters, roughly 8.0k o200k tokens by the current estimate;
- end-to-end `--no-skills` search and load selected `browser-automation` correctly.

The gateway routing eval currently scores:

- top-1: 92.5%;
- top-3: 100%;
- required top-3 gate: 80%.

Cross-harness probes also found:

- Codex already enforces a 2% skill-context budget and shortened descriptions during the probe;
- Hermes reports 18,471 bytes of skill index plus 59,252 bytes of schemas for 42 tools;
- OpenClaw injected 8,699 skill characters for 60 skills in a 25,918-character system prompt;
- Claude's tools-disabled one-turn request still created 18,747 cached input tokens, but Claude did not expose a trustworthy skill-only breakdown.

These findings argue for harness-native filtering rather than distributing the Pi extension everywhere. See `docs/HARNESS_PROMPT_SURFACE_AUDIT.md` and run `npm run test:skill-gateway` for current evidence.

## Tool surface

Skill routing and tool routing are separate concerns.

`tool-profiles` starts with a nine-tool lean surface and keeps the initial schema stable:

- `lean` — normal coding/file work plus `tool_lookup`;
- `search` — Exa/Librarian/rich retrieval;
- `orch` — Pi-native process orchestration; interactive PTY sessions remain separately discoverable through `tool_lookup`;
- `design` — design/gallery tools;
- `browser` — browser/retrieval evaluation;
- `cloudflare` — Codemode schema/execute;
- `full` — explicit escape hatch.

On Pi 0.80.7+, `tool_lookup` additively activates matched registered tools during its tool result. GPT-5.4+ receives those definitions through native deferred tool loading, so the original prompt/tool prefix remains cacheable. Tools loaded this way intentionally omit `promptSnippet` and `promptGuidelines`; changing either would still rebuild the system prompt.

Manual `/tools <profile>` and `+profile` remain explicit replacement controls, but replacements can invalidate the provider's cached prefix. The previous per-prompt regex switching was removed for that reason.

The original lean provider schema measured 9,105 characters at eight tools versus 16,658 at 13 tools. In an immediate before/after Pi probe, adding `tool_lookup` moved the lean schema from 9,322 characters at eight tools to 9,769 at nine tools (+447, 4.8%). After it loaded two Cloudflare tools, the next native Codex request still had nine top-level tools because the new definitions were anchored at the tool result instead of rewriting the prefix.

## Cross-harness policy

Skills are not blindly mirrored between Codex, Claude, Pi, Hermes, and OpenClaw.

Classes:

1. **Portable** — canonical under `~/.agents/skills`, intentionally copied to listed harnesses.
2. **Portable coding** — shared only with coding harnesses. Pi and Codex already discover `~/.agents/skills`.
3. **Harness-native** — remains in Hermes/OpenClaw/Claude/Pi unless deliberately generalized.
4. **Project-local** — remains under the repository that owns its domain context.

`config/skill-distribution.json` is the harness-target allowlist. `scripts/sync-agent-skills.mjs` changes only explicitly named target folders, supports per-skill symlinks, and backs up a conflicting named path before replacement. It never deletes unlisted native skills.

Trusted third-party skills have an additional source gate: `config/trusted-skill-sources.json` pins reviewed commits and directory hashes, while `scripts/manage-trusted-skills.mjs` materializes immutable vendor snapshots and activates only allowlisted skill directories. See `docs/TRUSTED_ENGINEERING_SKILLS.md`.

The recursive topology audit now includes:

- user roots;
- Claude plugin cache;
- Hermes user categories and built-ins;
- OpenClaw global/workspace roots;
- project-local `.agents`, `.claude`, and `.pi` skill roots under `~/code`.

Catalog inventory is not labeled as actual prompt cost. Only provider-request instrumentation counts as measured prompt/tool surface.

## Continuous improvement

Telemetry proposes investigations; it never writes skill instructions.

Use:

```bash
npm run propose:skill-maintenance
```

The report correlates gateway recommendations/loads with harness failures and clearly labels correlation as non-causal. A production skill edit requires repeated or reproducible evidence, causal diagnosis, a bounded replacement diff, an eval, and independent review.

Maintenance changes should remain size-neutral or shrink unless they add a tested capability. Remove obsolete text, move rare detail to references, and move deterministic behavior into scripts.

See `docs/SKILL_QUALITY_POLICY.md`.

## Update safety

`skill-update-checker` remains report-first. Scans do not mutate skills. The updater now recovers common upstream folder moves by matching unique skill-folder basenames and records the resolved path on a later safe apply.

The latest full scan found substantial upstream reorganizations and conflicts, so no bulk update was applied.

The trusted engineering set is deliberately separate from branch-following package updates. Fetch, diff, audit, evaluate, pilot, and explicitly move its immutable pin; Repository Updater does not own this lane.
